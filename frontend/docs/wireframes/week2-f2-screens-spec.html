ID Format: DA-XXXX-XX (alphanumeric, unique per school). Generated in bulk by backend when school purchases seats. Admin downloads CSV, distributes via WhatsApp or email to students.
How School ID Auth Works
1
School pays via Paystack. Backend auto-generates N unique codes (e.g. DA-8472-KX) and emails them as a CSV to the admin.
2
Admin distributes codes — prints a list, sends via WhatsApp, or reads out in class. Each student gets one unique code.
3
Student enters their code in the PWA. System auto-creates their account, stores device fingerprint. Code status → "Active". First and only time they enter it.
4
Return visits: the stored session token logs them back in automatically — no code re-entry needed. New device: old session revoked, new device fingerprint stored.
No passwords for org students. The access code is both the activation key and the identity. Students never need to remember anything once their device is registered.
Admin Dashboard Rules — For Dev Team
ScreenRouteKey Data SourceNotes
SCR-10 Student Overview /admin/students topic_reviews table · daily_recall_queue · users table AI Alert fires when ≥60% students below 60% on a topic in 7 days. Stat cards aggregate from topic_reviews. Table is paginated — show 20 rows, load more.
SCR-11 Student Drill-Down /admin/student/[student_id] topic_reviews · chat_sessions · chat_messages Teacher read-only. Cannot edit or delete any data. EF column from topic_reviews.ease_factor. Chat logs load on demand — not pre-fetched with the page.
SCR-12 Access Code Management /admin/codes access_codes table "Download All IDs" generates CSV from access_codes where org_id = admin's org. "Download Unused" filters status = 'pending'. Codes are generated server-side on Paystack webhook — admin never creates them manually.
